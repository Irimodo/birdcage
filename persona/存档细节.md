# 存档细节

> 定义"记忆"怎么存、存什么、怎么被读回提示词。程序按本文件实现，改这里的规则不需要改代码逻辑——数值在 `config.json` 与 `data/` 里。

## 一、文件分工

| 文件 | 位置 | 归属 | 内容 |
|---|---|---|---|
| `config.json` | 根目录 | 用户可改 | API base URL、API Key、模型名、端口、打字速度、字号、默认背景/服装/BGM |
| `data/state.json` | 根目录/data | 程序写 | 当前场景状态：背景 id、表情、服装、CG、BGM、是否静音 |
| `data/memory.json` | 根目录/data | 程序写 | 长期记忆条目（见第三节） |
| `data/chat.jsonl` | 根目录/data | 程序写 | 原始对话流水，一行一轮，用于回溯与重建 |
| `data/uploads/` | 根目录/data | 程序写 | 用户发来的图片/PDF/Word/Excel/视频，按日期存放 |
| `persona/*.md` | 根目录/persona | **用户手改** | 人设、总纲、我的档案、素材清单、本文件 |

原则：**设定在 persona（人读），状态在 data（机读）。** 两者不混。

## 二、提示词拼装顺序（每次请求）

1. `system`：人设（角色人设.md 全文）+ 关系基线 + 输出格式硬规则
2. `system`：当前时间（程序注入，形如 `2026-11-25 星期三 21:40（UTC+8）`）+ 场景状态（背景中文名、表情、BGM 名）
3. `system`：我的档案（全文）+ 长期记忆（按相关度取前 N 条，默认 12）
4. `system`：剧情总纲（**全量**，按用户 N3 选择"细节最全"；若超出预算则按 `STORY_BUDGET` 截断到最近相关的章节，默认不截断）
5. `messages`：最近 12 轮对话原文（超出的折叠成一条摘要）
6. `user`：本轮输入（附件已在此前一步转成文字摘要，见第四节）

token 预算上限默认 20k（`config.json` 可调 `max_prompt_tokens`）。超了按"总纲 → 记忆 → 历史"的顺序砍，人设与档案永不砍。

## 三、记忆条目

一条记忆 = `{id, t, kind, text, tags, weight}`

- `kind`：`fact`（事实：她在哪上班、几点下班）、`event`（事件：今天发生了争执）、`prefer`（偏好：怕黑、喜欢草莓）、`promise`（约定：下次要带什么）、`mood`（情绪：这周很累）。
- `weight` 1–5，由模型在回复后自评（"这条对以后有多重要"）；取用时按 `weight × 时间衰减` 排序。
- 写入时机：每轮回复后，模型额外输出一段 `MEMO:`（不显示给用户），程序解析后落盘。没有可记的就输出 `MEMO: -`。
- 不去重到只剩一条：同类多条按时间保留，读的时候合并成一句（"她最近三次都说加班很累"）。
- 上限 400 条，超出时把 `weight` 最低且最旧的 50 条压成一条 `kind=fact` 的长句。

## 四、附件

- 支持：png/jpg/gif/webp、mp4/mov、pdf、docx、xlsx、txt/md。
- 图片与视频：存 `data/uploads/`，同时生成本地缩略图；提示词里只写"她发来一张图（<文件名>，内容摘要）"。
- 文档：txt/md 直读；pdf/docx/xlsx 用纯标准库尽量抽取文字（pdf 走 `zlib` 解流 + 简易文本层，抽不到就只记"发来了一份 PDF，页数 N"）。
- 单条附件 > 8MB 时只记元信息，不塞正文。

## 五、跨启动的"连续性"

启动时按顺序读：`persona/*.md` → `config.json` → `data/memory.json` → `data/chat.jsonl` 末尾 30 轮 → `data/state.json`。

界面恢复上一次的背景、表情、BGM 与音量；开场第一句话由模型根据"距离上次对话过了多久"生成——**超过 6 小时算"隔了一段时间"，超过 3 天算"好久不见"**，不硬说"欢迎回来"。

## 六、重置

- 设置面板里有"清空记忆"，只删 `memory.json` 与 `chat.jsonl`，不动 persona 与素材。
- 不存在"新游戏/读档"这种界面概念。想回到某个时间点，自己备份 `data/` 文件夹即可。
